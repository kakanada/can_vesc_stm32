# vesc

Портируемая C-библиотека для обмена с контроллерами электропривода **VESC** по
шине **CAN / FDCAN** на микроконтроллерах **STM32**. Предназначена для
встраиваемых систем, где нужно управлять несколькими VESC одновременно
(колёсные приводы, роботизированные платформы, электротранспорт) быстро,
неблокирующе и без ручного бит-баттлинга протокола.

## Зачем нужна

VESC-контроллеры отдают телеметрию и принимают команды по CAN в виде
однокадровых пакетов (скорость, ток, скважность и т.д.) и статусных пакетов
(обороты, ток, температура, напряжение и др.). Реализовать это "с нуля" —
разбор идентификаторов, масштабирование величин, очередь на переполнение
буфера периферии, поддержку нескольких контроллеров и нескольких шин —
рутинная и легко ошибающаяся работа. Библиотека берёт это на себя и
предоставляет простой API: заполнил структуру конфигурации → получил хэндл →
дальше просто вызываешь функции отправки команд и читаешь телеметрию из
структуры.

## Поддерживаемые платформы

- **Любой STM32H7** и другие микроконтроллеры с периферией **FDCAN**
  (бэкенд выбирается автоматически по `HAL_FDCAN_MODULE_ENABLED`).
- **Любой STM32F4** и другие микроконтроллеры с классическим **bxCAN**
  экенд выбирается автоматически по `HAL_CAN_MODULE_ENABLED`).
- Библиотека сама определяет доступный бэкенд на этапе компиляции — один и
  тот же код работает на обеих сериях без правок.
- Поддержка нескольких независимых CAN-шин одновременно (например, часть
  VESC на CAN1, часть — на CAN2 / FDCAN1 / FDCAN2).

## Основной функционал

- Регистрация произвольного числа VESC (лимит настраивается,
  по умолчанию 24 суммарно по всем шинам) через `VESC_CAN_Init()`.
- Отправка всех "простых" однокадровых команд протокола VESC: duty cycle,
  ток, тормозной ток, целевая скорость (эл. и механические RPM с учётом
  числа полюсов мотора), позиция, относительные варианты тока/тормоза,
  handbrake-ток.
- Неблокирующая отправка с программной очередью "на случай если аппаратный
  буфер периферии переполнен" и досылкой по кругу (round-robin) между всеми
  зарегистрированными VESC на шине — ни один контроллер не остаётся без
  команд надолго, даже под высокой нагрузкой на шину.
- Разбор полной телеметрии: обороты, ток, скважность, накопленные Ач/Втч,
  температуры FET и мотора, входной ток, позиция (PID), тахометр, входное
  напряжение, ADC-каналы, PPM — плюс кастомный статусный пакет с состоянием
  тормоза и произвольного цифрового датчика, подключённого к VESC.
- "Губернаторы" скорости и тока — программные (не встроенные в прошивку
  VESC) ограничители, которые действуют и напрямую на отправляемую команду,
  и "перекрёстно" по измеренной телеметрии (например: управляете током, но
  скорость не превышает заданный потолок).
- Память положения между включениями — сохранение скорректированного угла
  вала в backup-регистры RTC (battery-backed), чтобы после выключения и
  повторного включения VESC система координат не "съезжала".
- Callback-обработчик кастомного цифрового датчика, подключённого к VESC —
  вызывается при получении соответствующего статуса.
- Программная имитация VESC (без физической шины) для отладки и разработки
  верхнеуровневой логики до подключения реального железа.

## Как использовать

```c
#include "motor_vesc.h"

VESC_Handle_t *front_left;

void MotorsInit(void)
{
    VESC_Config_t cfg = {
        .hcan       = &hfdcan1,
        .vesc_id    = 10,
        .pole_count = 14,
    };
    front_left = VESC_CAN_Init(&cfg);
}

void ControlLoopTick(void)
{
    VESC_CAN_SendSpeed(front_left, 8000.0f);   /* электрические RPM */

    const VESC_Telemetry_t *t = &front_left->telemetry;
    float current = t->current;
    float temp    = t->temp_fet;
}
```

```c
/* Диспетчеризация приёма/отправки — вызывается из своих HAL callback-ов */
void HAL_FDCAN_RxFifo0Callback(FDCAN_HandleTypeDef *hfdcan, uint32_t RxFifo0ITs)
{
    VESC_CAN_RxFifo0_Handler(hfdcan, RxFifo0ITs);
}

void HAL_FDCAN_TxFifoEmptyCallback(FDCAN_HandleTypeDef *hfdcan)
{
    VESC_CAN_TxComplete_Handler(hfdcan);
}
```

Полное описание всех функций, обязательные настройки CubeMX и подробные
пояснения к каждой подсистеме (губернаторы, память положения, имитация,
кастомный датчик) — в комментариях `vesc.h`.

## Требования

- STM32 HAL с включённым `HAL_FDCAN_MODULE_ENABLED` либо
  `HAL_CAN_MODULE_ENABLED`.
- Для памяти положения — включённый `HAL_RTC_MODULE_ENABLED` и
  проинициализированный в CubeMX RTC (для сохранения через полное
  обесточивание платы дополнительно нужна батарея на выводе VBAT).

## Честные ограничения

- Отправка полного набора команд конфигурации VESC (через
  `COMM_SET_MCCONF_TEMP` и аналогичные) не реализована — библиотека
  работает только с "простыми" однокадровыми командами протокола CAN.
- Точная внутренняя семантика команды `SET_CURRENT_HANDBRAKE` в прошивке
  VESC документально не подтверждена — для задач принудительного
  удержания вала рекомендуется `VESC_CAN_SendCurrentBrake()`.
